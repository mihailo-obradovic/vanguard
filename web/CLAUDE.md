# web/ — Nuxt frontend

The Nuxt 4 SPA (`ssr: false`). This directory is only the source tree — the app is configured from the repo root: `nuxt.config.ts` (with `srcDir: 'web/'`), `package.json`, `tsconfig.json`, `vitest.config.ts`, `.oxlintrc.json`, `.oxfmtrc.json`. pnpm only.

Paths below are relative to the repo root. The `catalyst/` documents are normative for how this code is written; this file only says what lives where.

## Structure

- `app.vue` / `error.vue` — entry and error shells; `error.vue` renders in `layouts/Empty.vue` (a self-scrolling, centred shell with no navbar — `catalyst/features/011_error-page.md`), every page in `layouts/Default.vue`. Below `lg` its nav links and auth controls move into a vendored `ui/sheet` drawer, both renderings drawn from one `links` list; the colour-mode toggle and language picker stay in the bar at every width.
- `assets/styles/main.css` — the design tokens (shadcn's semantic set carrying Dracula, in both faces, plus the roles this product has that shadcn names none of: `--success`, `--warning`, `--scroll-edge`), the `@theme inline` mapping Tailwind reads, and the few base-element rules. The only global CSS there is.
- `components/_shared/` — auto-imported shared components (`components.dirs` in `nuxt.config.ts`); everything else is explicitly imported. Everything here is built on vendored shadcn-vue components and Tailwind utilities, except the two primitives this project owns on purpose: `UIReservedLabel.vue` (layout stability) and `UIScrollArea.vue` (the scroll-edge affordance) — nothing upstream replaces either. `FormDialog.vue` is the dialog every form dialog is built on (`web/components/ui/dialog`, `useConfirmOnEnter`, `UIScrollArea` for the scrollable body; `catalyst/decisions/014_ui_shadcn-dialog-auth-composition.md`). `AuthCard.vue` is the shell the remaining standalone auth screen (`password-reset`) is made of. `RoleBadge.vue` is the users table's status pill and `VerificationBadge.vue` is shared between the table and `UserCard.vue`'s inline verification row; both are vendored `Badge` with the project's own `success`/`warning` variants, whose tokens `main.css` declares because shadcn names no such role.
- `components/<resource>/` — feature components, imported explicitly: `users/UserFormDialog.vue`, `users/UserGqlFormDialog.vue` own the forms their pages used to hold inline, and `users/UserDeleteDialog.vue` the delete confirmation; `users/{Login,Register,ForgotPassword}Dialog.vue` are opened from `web/layouts/Default.vue`, not from a page; `users/UserCard.vue` is `pages/profile.vue`'s entire content — a true inline edit, not a dialog (`catalyst/decisions/014_ui_shadcn-dialog-auth-composition.md`).
- `composables/` — `useAppQuery` / `useAppMutation` (the only query/mutation wrappers components may use), `useValidationErrors` / `useExternalErrors` (server-422-to-Regle bridge), `useFieldAria` (the `id`/ARIA pairing a `ui/field` composition needs — `ui/field` wires none of it), `useFocusReturn` (where focus goes when an overlay closes after its opener has unmounted — Reka's own restore lands on `<body>` then), `useCookieConsent`.
- `i18n/` — message catalogs and the Vue I18n config; has its own `CLAUDE.md`.
- `mocks/` — test-only: the MSW server, its lifecycle setup file, the request recorder, schema-parsed fixtures, and per-resource handlers. Never imported by shipped code.
- `middleware/auth.global.ts` — the only route middleware; a thin wrapper over the pure, unit-tested `utils/authRedirectLogic.ts`.
- `pages/users.vue` composes the vendored `Table` inside a plain `overflow-auto` region scrolling both axes (as does `graphql-demo.vue`) — the tables are wider than a phone — and not inside `UIScrollArea`, whose edge rules would only double the bordered shell and the header band that already mark the clipped edges: the shell around it carries the border and radius, the scrolling region carries none, and the sticky header needs its own opaque fill to cover the rows passing under it (`catalyst/stacks/frontend/_common/scroll-affordance.md`). Deleting a user is `components/users/UserDeleteDialog.vue`, an `AlertDialog` rather than a `Dialog` — a destructive confirmation, with the role and the cancel-focused default that go with it.
- `pages/` — file-based routes: `index`, `home`, `profile`, `users`, `graphql-demo`, plus the one remaining auth page, `password-reset` (reads `?token=&email=`; login/register/forgot-password are dialogs now, not routes — `components/users/`).
- `plugins/` — `auth-loader.ts` (restores the session before first render). Toasts need no plugin: `app.vue` mounts the vendored `components/ui/sonner` `<Toaster />` once, and `utils/toast.ts` is the seam in front of it.
- `regle-config.ts` — the `@regle/nuxt` setup file: localized messages for the built-in validation rules.
- `services/` — one `<resource>.api.ts` per resource (auto-imported via `imports.dirs`); `services/queries/` holds the `use<Resource>Queries.ts` composables. Two-layer rule: every resource has both files. A resource served over GraphQL instead uses `<resource>.gql.ts` + `use<Resource>GqlQueries.ts` — the same two layers, the same wrappers, only the transport differs.
- `stores/useAuthStore.ts` — the only Pinia store.
- `types/` — shared domain types and Zod schemas (`auth.ts`, `user.ts`) plus ambient declarations.
- `utils/` — `fetcher.ts` (CSRF cookie + 419-retry), `gqlFetcher.ts` / `gql.ts` (GraphQL over the same fetcher, translating GraphQL errors into the REST-equivalent `FetchError`), `handleApiError.ts` / `setupQueryErrorHandling.ts` (central error handling), `parseResponse.ts` (Zod), `chainAfter.ts` (the options-passthrough ordering rule), `toast.ts`, `authRedirectLogic.ts`.

Tests live in a `_tests/` subdirectory of the directory holding the code under test — `_tests/` (for `app.vue`, `error.vue` and `regle-config.ts`), `utils/_tests/`, `services/_tests/`, `services/queries/_tests/`, `composables/_tests/`, `stores/_tests/`, `i18n/_tests/`, `plugins/_tests/`, `components/_shared/_tests/`, `layouts/_tests/` — one spec per source file, same base name. The API is mocked at the wire with MSW, never by stubbing the fetcher or a service module (`catalyst/stacks/frontend/nuxt/testing.md`).

## Local invariants

- `auth.global.ts` runs on every navigation; redirect logic lives in `utils/authRedirectLogic.ts` so it stays unit-testable — change the logic there, not in the middleware.
- **Converted forms compose `components/ui/field` directly** — `<Field :data-invalid>` + `<FieldLabel :for>` + `<Input v-bind="…control">` + `<FieldError :id>` — with `useFieldAria(() => r$.<field>.$errors)` supplying the generated `id`, the error `id`, and the `aria-invalid`/`aria-describedby` pair, the last set only while the field is invalid. There is no project wrapper by design (`catalyst/stacks/frontend/nuxt/ui/shadcn-vue/components.md`): `ui/field` is the field contract in the framework's own vocabulary. The vendored `FieldError` carries this project's reserved two-line height as an annotated deviation — upstream unmounts it when valid, which reinstates the jump `layout-stability.md` forbids.
- A dialog is a `<FormDialog>`: it owns the overlay, the dialog role and `aria-modal`, the title it is labelled by, initial focus, the Tab trap and focus restoration on close (to its `returnFocusTo` when the opener is gone — the layout passes the control that started a dialog hand-off), and it bounds its own height and scrolls its body — the overlay is fixed and centred and `main.css` pins the page to `overflow-y: hidden`, so an unbounded panel taller than the viewport puts its submit button somewhere no scroll can reach. The body is a `<UIScrollArea>`, which marks whichever edge is currently hiding content. Its actions sit in the dialog footer, outside any `<form>`: submission travels as the `confirm` event, which is also what Enter reaches through `useConfirmOnEnter`. Pages hold no template refs and no focus watchers.
- A **destructive** confirmation is an `<AlertDialog>`, not a `<FormDialog>` — it carries `role="alertdialog"` and puts initial focus on Cancel rather than on the button that does the damage (`components/users/UserDeleteDialog.vue`). Its confirm is a plain `Button`, never `AlertDialogAction`: that part is Reka's `DialogClose` and closes before its click listener runs, so an async confirmation built on it closes without acting.
- A dialog form takes `serverErrors` from the page that owns the mutation and emits its finished payload — the page never reaches into it, and the shaping rules (which fields travel, and when) live with the form (`catalyst/stacks/frontend/nuxt/validation.md`, "Two component shapes"). Its subject prop decides the mode; there is no parallel `isEditMode` flag.
- An auth screen is an `<AuthCard>`: the card, its title and hint, the form element, the submit control (including the label swap while a request is in flight) and the footer's link styling all live there. The remaining auth page carries no `<style>` block at all — a new one is a sign something belongs in the card instead. Login/register/forgot-password are dialogs instead, built on `<FormDialog>` (shadcn-vue's `Dialog`), not `<AuthCard>`.
- Colours and radii come from the tokens in `assets/styles/main.css`, reached through Tailwind utilities (`bg-card`, `text-muted-foreground`, `rounded-md`) — a literal hex or `rgb()` in a component is a missing token, not a local choice. Tokens are named for the role, so two roles may share a value (`--secondary` and `--muted` are both `#e8eaea` in the light face) and still diverge later. A new role gets its token in both faces, with its contrast measured, before any component uses it.
- A list's loading branch gates on the query's `isPending`, never `isLoading`: `isLoading` is true for background refetches too, so gating on it tears the list down on every invalidation and defeats the `placeholderData` the query wrapper sets (`catalyst/stacks/frontend/nuxt/data-layer.md`).
- Components never call `useQuery`/`useMutation` or the fetcher directly; the service → query-composable → component chain is the only path to the API. This holds for GraphQL too — `gqlFetcher` is a service-layer tool, never called from a component (`catalyst/features/007_graphql-api.md`).
- GraphQL documents are plain strings — the `gql` tag is an identity function and nothing validates them at build time, so a mistyped field fails at runtime. Verify new documents against `graphql/schema.graphql` (GraphiQL at `/graphiql` in dev); the codegen revisit trigger is recorded in `catalyst/decisions/007_infra_graphql-alongside-rest.md`.
- The backend contract this app is built against is a protected area — see Protected Areas in `catalyst/architecture.md`.
- Every user-facing string goes through the catalogs in `i18n/`; strings the backend returns already localized are displayed as received. Plain `.ts` helpers take the translator from `useNuxtApp().$i18n` inside the function, never at module scope.
- Which shell, plugin, and component files are tested, and which are left to the live browser walk on purpose, is recorded in `catalyst/operations.md` — check there before reading a 0% as an oversight.
